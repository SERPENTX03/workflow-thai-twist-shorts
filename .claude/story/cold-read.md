# Cold read — ทดสอบว่าหักมุมเดาง่ายไหม และคนดูตามทันไหม (ใช้ร่วม long และ short)

คนเขียนรู้คำตอบอยู่แล้ว จึงตัดสินเองไม่ได้ว่าเรื่องเดาง่ายไหม หรือฟังรอบเดียวแล้วเข้าใจไหม การให้คะแนนตัวเอง 0–10 ไม่บอกอะไร ขั้นตอนนี้ให้ **ผู้อ่านที่ไม่เคยเห็น brief** อ่านบทที่ถูกตัดกลางเรื่อง แล้วเดา มันแทน scorecard เดิม

กฎที่ใช้แก้เมื่อไม่ผ่านอยู่ใน `story-rules.md` → *Hiding the twist* และ `longform-rules.md` → *Concealment* ไฟล์นี้มีแค่วิธีทดสอบ

## เมื่อไร

| รอบ | เมื่อไร | อ่านอะไร | ทำไม |
|---|---|---|---|
| A | ก่อนส่ง outline / brief ให้ผู้ใช้ | beats ที่เขียนเป็นร้อยแก้วตามลำดับที่คนดูจะรู้ (ไม่มีหัวข้อ Twist, Clues, Continuity) | ถูก จับโครงที่เดาง่ายก่อนเขียนบท |
| B | หลังเขียน `story.json` ครบ **ก่อนลงเสียง** | ไฟล์จาก `npm run coldread -- episodes/<slug>` | ของจริง: ถ้อยคำของผู้บรรยายคือที่ที่ความลับรั่ว และหลังจากนี้การแก้ข้อความเสียเครดิตเสียง |

รอบ B บังคับ รอบ A ทำเมื่อเรื่องเป็นแนวสืบสวนหรือมีผู้ต้องสงสัยมากกว่าหนึ่งคน

## วิธีทำ (รอบ B)

1. `npm run coldread -- episodes/<slug>` ได้ `out/<slug>-coldread/cut-25.txt`, `cut-50.txt`, `cut-75.txt`, `full.txt` (เรื่องยาว) หรือ `cut-60.txt`, `full.txt` (Shorts) ตัดที่จุดอื่นได้ด้วย `--cuts 40,70` (เปอร์เซ็นต์) หรือ `--shots 22,150` (เลขช็อตสุดท้ายที่ให้อ่าน) สำหรับ Shorts ให้ตัดที่ช็อตก่อนจังหวะพลิก
2. ไฟล์มีแค่ชื่อเรื่อง ชื่อบท และประโยคที่คนดูได้ยิน ไม่มี `note`, `view`, ชื่อ scene เพราะสิ่งเหล่านั้นเอ่ยชื่อเบาะแส
3. เปิด **ผู้อ่านใหม่หนึ่งคนต่อหนึ่งจุดตัด** (subagent ที่ไม่มีบทสนทนานี้ หรือแชตใหม่) วางข้อความของจุดตัดนั้นลงใน prompt ตรงๆ ห้ามให้ path ของ repo, brief, story.json หรือสรุปเรื่อง ผู้อ่านที่อ่านจุดตัดหนึ่งแล้วใช้กับจุดตัดอื่นไม่ได้ และผู้อ่านที่เห็นเฉลยแล้วใช้ซ้ำไม่ได้
4. ถามตามหัวข้อ "คำถามก่อนเฉลย" แล้วส่ง `full.txt` ให้คนเดิม ถามต่อตาม "คำถามหลังเฉลย"
5. ถ้าเครื่องมือเปิดผู้อ่านใหม่ไม่ได้ ให้บอกผู้ใช้ว่าทำรอบนี้ไม่ได้ และขอให้เขาวาง `cut-50.txt` ในแชตใหม่เอง อย่าข้ามเงียบๆ และอย่าเดาแทนผู้อ่าน

### คำถามก่อนเฉลย (วางต่อท้ายข้อความที่ตัด)

```
นี่คือบทพูดของคลิปเล่าเรื่องหักมุม ถูกตัดกลางเรื่อง คุณไม่เคยดูเรื่องนี้ ตอบจากข้อความนี้เท่านั้น ห้ามเปิดไฟล์ใด
1. ตอนจบจะเฉลยว่าอะไร เดา 3 อันดับ พร้อมความมั่นใจเป็นเปอร์เซ็นต์ (รวมกันไม่เกิน 100)
2. แต่ละข้อ ประโยคไหนทำให้คิดอย่างนั้น ยกประโยคมา
3. ตอนนี้คุณรออยากรู้อะไรที่สุด
4. มีตรงไหนที่ฟังรอบเดียวแล้วไม่เข้าใจ
5. เล่าเรื่องถึงตรงนี้ให้เพื่อนฟังใน 3 ประโยค: ใครอยากได้อะไร, อะไรขวางอยู่, โลกในเรื่องนี้ทำงานยังไง (ถ้ายังไม่รู้ข้อไหน ให้บอกว่าไม่รู้)
6. ตอบจากความจำ ไม่ย้อนอ่าน: ตัวละครที่จำได้ ชื่ออะไร เป็นใคร (ญาติของใคร อยู่ที่ไหน) และใครที่จำได้ว่ามีแต่ไม่แน่ใจว่าเป็นใคร
```

### คำถามหลังเฉลย (ส่งเรื่องเต็มให้คนเดิม)

```
นี่คือเรื่องเต็ม
1. เฉลยตรงกับที่เดาไว้ข้อไหนไหม
2. ยุติธรรมไหม ยกเบาะแสที่จำได้ว่าเคยเห็นก่อนเฉลยมาอย่างน้อย 2 อย่าง ถ้าจำไม่ได้ให้บอกว่าจำไม่ได้
3. จุดไหนที่คนคอมเมนต์จะแย้งได้ในประโยคเดียว (ตรรกะ แรงจูงใจ ลำดับเวลา)
4. ประโยคไหนที่อยากเล่าต่อหรือแคปเก็บ
5. สรุปทั้งเรื่องใน 3 ประโยค และตอนจบเกิดขึ้นได้เพราะอะไร
```

## ตัดสิน

| ผล | เกณฑ์ | ทำอะไร |
|---|---|---|
| **เดาง่าย** | คำตอบจริงเป็นอันดับ 1 ที่จุดตัด 50 % (เรื่องยาว) หรือที่จุดตัดก่อนจังหวะพลิก (Shorts) หรือได้ความมั่นใจ ≥ 70 % ที่จุดตัดใดก็ตามก่อนสลิป | ประโยคที่ผู้อ่านยกมาในข้อ 2 คือรายการแก้ แก้ตามกฎซ่อน (ถอดคำชี้ของผู้บรรยาย ให้เบาะแสมีงานบังหน้า เพิ่มน้ำหนักให้ผู้ต้องสงสัยอื่น) |
| **ดี** | คำตอบจริงอยู่ใน 3 อันดับที่จุดตัด 75 % แต่ไม่ใช่อันดับ 1 ที่ 50 % | ไม่ต้องแก้: คนดูสงสัยแต่ยังไม่แน่ใจ คือความตึงที่ต้องการ |
| **ไม่ยุติธรรม** | หลังเฉลย ผู้อ่านยกเบาะแสที่จำได้ไม่ถึง 2 อย่าง หรือบอกว่าเฉลยมาจากไหนไม่รู้ | เบาะแสจมเกินไป: วางให้ชัดขึ้นหนึ่งครั้ง หรือเพิ่มช็อตที่มันอยู่ในเฟรม |
| **มืดแปดด้าน** | ที่ 75 % ผู้อ่านไม่มีข้อเดาที่ใกล้เลยและบอกว่าไม่รู้จะรออะไร | เพิ่มคำถามค้างและผู้ต้องสงสัยที่จับต้องได้ ไม่ใช่เพิ่มเบาะแสของคำตอบจริง |
| **งง** (ตามไม่ทัน) | ที่จุดตัด 25 % ข้อ 5 ยังบอกไม่ได้ว่าตัวเอกอยากได้อะไร หรือที่ 50 % ยังบอกกฎของโลกไม่ได้ หรือข้อ 6 สับสนตัวละคร ≥ 2 คน หรือข้อ 4 มีจุดที่ไม่เข้าใจ ≥ 3 จุด หรือหลังเฉลยข้อ 5 อธิบายไม่ได้ว่าตอนจบเกิดขึ้นเพราะอะไร | แก้ตาม `longform-rules.md` → *Comprehension load* (Shorts: `story-rules.md` → *Narrative clarity*): พูดกฎหลักให้เร็วขึ้นและตรงขึ้น, ตัดชื่อ/รวมเป็นกลุ่ม, ปิดคำถามเก่าก่อนเปิดใหม่, เติมประโยค "เข้าไปอยู่ตรงนั้นได้ยังไง" อย่าเพิ่มเบาะแส |
| **รูโหว่** | ข้อ 3 หลังเฉลยได้ข้อแย้งที่ตอบไม่ได้ในประโยคเดียว | แก้เรื่อง หรือเพิ่มประโยคที่ปิดรูนั้น |

- แก้แล้วทดสอบใหม่ด้วย **ผู้อ่านคนใหม่** ทำได้ **ไม่เกิน 2 รอบ** ถ้ายังเดาง่าย ให้หยุดแล้วเอาตารางผลไปให้ผู้ใช้ตัดสิน อย่าวนต่อเอง
- การแก้ที่แตะ twist หรือแก่นเรื่องต้องให้ผู้ใช้ตัดสิน (เหมือน fun pass ข้อ ⚠)
- **งง** แก้ก่อน **เดาง่าย**: คนดูที่ตามไม่ทันจะไม่อยู่ถึงหักมุม และผู้อ่านที่เป็น model อ่านตัวหนังสือซ้ำได้ ส่วนคนดูได้ยินรอบเดียว ถ้า model ยังสับสน คนดูจริงหลุดไปนานแล้ว ตัวอย่าง: `same-child` (ผู้ชมบอกว่าดูไม่รู้เรื่อง) ชื่อ 15 ชื่อ กฎของโลกราว 8 ข้อ กฎหลักพูดตรงๆ ครั้งแรกที่ 44 %
- การเดาถูกเพราะรู้แนวช่อง ("ช่องนี้คนใจดีเป็นคนร้ายทุกเรื่อง") ก็นับว่าเดาง่าย: ดู *casting tell* ในกฎซ่อน

## รายงานให้ผู้ใช้

ตารางเดียว: จุดตัด · ข้อเดาอันดับ 1 และความมั่นใจ · คำตอบจริงอยู่อันดับไหน · ประโยคที่ทำให้เดาได้ · สรุป 3 ประโยคของผู้อ่าน (ถูกไหม) · ตัวละครที่สับสน ตามด้วยผลหลังเฉลย (ยุติธรรมไหม รูโหว่ ประโยคเด็ด) และสิ่งที่แก้ไปแล้ว ถ้าทำรอบนี้ไม่ได้ ให้บอกตรงๆ ว่าไม่ได้ทำ

## ขีดจำกัด

ผู้อ่านเห็นแต่คำพูด ไม่เห็นภาพ เบาะแสที่อยู่ในภาพอย่างเดียว (insert ของมือ รูป มิเตอร์) จึงไม่ถูกทดสอบ ถ้าผลออกมา "ไม่ยุติธรรม" แต่เบาะแสอยู่ในภาพครบ ให้เปิดเฟรมของเบาะแสดูว่าอ่านออกจริงไหมก่อนไปแก้บท และผู้อ่านที่เป็น model มักเดาเก่งกว่าคนดูทั่วไป ผ่านเกณฑ์นี้จึงเป็นขั้นต่ำที่ปลอดภัย ไม่ใช่การรับรองว่าไม่มีใครเดาได้
