# /create-story-short — ตรวจ เติม ยกระดับ ก่อนเขียนเรื่องสั้น

ฟอร์แมตตายตัว: **แนวตั้ง 9:16 สั้นไม่เกิน ~2 นาที** ไม่ต้องถามฟอร์แมต ถ้า prompt ใหญ่เกินกว่าจะอัดใน 2 นาที (หลายองก์ ตัวละครเกิน 3 คน หลายสถานที่) ให้บอกในบรรทัดเดียวว่า `/create-story-long` เหมาะกว่า หรือเสนอวิธีย่อให้เหลือแกนเดียว

Skill นี้ **ไม่มีกฎของตัวเอง** มันอ่านกฎจริงแล้ววัดเรื่องกับกฎนั้น และไม่เขียน `story.json` ที่เป็นเนื้อเรื่อง

## 0. อ่านก่อนทำอะไร

1. `CLAUDE.md` (ชนะทุกอย่าง)
2. `.claude/skills/thai-twist-short/references/story-rules.md` — family, shape ต่อองก์, knowledge layer, cast, twist types, clue, **Twist checklist**, Narrative clarity, Thai caption voice
3. `.claude/skills/thai-twist-short/references/ref-library.md` — รูปแบบของคลิปยอดวิวสูง
4. `.claude/story/fun-pass.md` — เกณฑ์ยกระดับความสนุก และ `.claude/story/cold-read.md` — วิธีทดสอบว่า twist เดาง่ายไหม
5. `ls episodes/` และ `series/` — อย่าซ้ำ premise ถ้าเป็นภาคต่อ ให้อ่าน `story.json` ตอนล่าสุดและ series bible ด้วย (และชี้ไป `/twist-next` ถ้าผู้ใช้ต้องการแค่ต่อตอน)
6. `universe/bible.md` และ `universe/canon.json` — กฎโลก สถานที่ ตัวละคร canon ระดับการเชื่อม (ถ้าไฟล์ไม่มี ข้าม §1.5 แล้วบอกผู้ใช้บรรทัดเดียว)

## 1. Intake — ถอด prompt เป็น Story Brief ดิบ

จาก `$ARGUMENTS` สรุปเป็นตารางสั้น: premise · family (Survival "ถ้า…" / Haunting twist / ตำนานไทย — ถ้า prompt ไม่ชัดให้เดาจากโทน) · สถานที่ · ภัยหรือกฎ · twist (ถ้ามี) · ตัวละคร · ความยาว · โทน · เป็นซีรีส์ไหม

ช่องที่ prompt ไม่ได้บอก **เติมค่าเริ่มต้นเองและมาร์ก `(เดา)`** ไม่ต้องถาม ถามเฉพาะเมื่อทิศเรื่องเปลี่ยนจริง รวมครั้งเดียวไม่เกิน 3 ข้อ (ใช้ AskUserQuestion) ถ้า prompt เฉลย twist มาแล้ว ห้ามถามเรื่อง twist

## 1.5 Universe link — คิดเรื่องการเชื่อมก่อนวัด

ทำหลัง intake ก่อน audit ตอบ 5 ข้อสั้นๆ ตามที่ `universe/bible.md` กำหนด ทุกข้อเติมค่าเริ่มต้นเองและมาร์ก `(เดา)` ไม่ต้องถาม:
1. **ระดับการเชื่อม 0–4** ค่าเริ่มต้นคือ 0–2 เสนอระดับ 3–4 เฉพาะเมื่อเนื้อเรื่องต้องการจริง
2. **สถานที่** ใช้ `places` ใน canon (ระบุรหัส) หรือ "สถานที่ใหม่" พร้อมเหตุผลว่าทำไมที่เดิมใช้ไม่ได้ และอยู่ตรงไหนของแผนที่
3. **ตัวละคร canon ที่ปรากฏ** (เช่น `wichai`) เฉพาะที่เรื่องต้องการ ถ้าไม่ได้ใช้ก็ไม่ต้องใส่ ห้ามใช้หน้า canon เป็นตัวเอกอื่น ตัวเอกประจำเรื่องต้องเปลี่ยนชื่อ + จุดเด่น + เสียง
4. **ไม่ขัด hard canon** ตรวจสถานะตัวละคร เหตุการณ์ และลำดับเวลา ถ้าขัด ให้แก้เรื่อง ไม่แก้ canon (เว้นผู้ใช้สั่ง)
5. **สิ่งที่จะลง canon ใหม่** ข้อเท็จจริงหรือ thread ที่เรื่องนี้เพิ่ม และ thread ที่เรื่องนี้ตอบ (ต้องให้ผู้ใช้อนุมัติ)

กฎเหล็ก: ปมหลักต้องปิดในตัวเอง ไม่เฉลยปมของเรื่องอื่น ดูเดี่ยวๆ ได้ ถ้าเรื่องนี้ต้องดูเรื่องก่อนถึงจะเข้าใจ ให้ตัดการเชื่อมออกหรือลดระดับ และอย่า bend เรื่องให้ตรงสถานที่ที่มีอยู่ ถ้าเรื่องดีกว่าเมื่อเป็นระดับ 0 ก็ปล่อยเป็นระดับ 0

## 2. Gap audit — วัดกับ Twist checklist

ไล่ทุกข้อของ **Twist checklist (gate for step 1)** ใน `story-rules.md` ให้ ✓ / ✗ / (เดา) พร้อมเหตุผลบรรทัดเดียวต่อข้อที่ ✗ โดยเฉพาะ:
- hook ที่เฟรม 0 = สถานที่ + ภัยหรือตัวเลข (≤ ~12 ตัวอักษรไทย) และคำถามที่ทำให้ไม่กดข้าม
- twist ยุติธรรม: ทุกเหตุการณ์ก่อนเฉลยยังสมเหตุสมผลหลังเฉลย, clue 3–5 จุดแต่ละจุดโผล่ ≥ 3 ครั้ง ไม่มีใครพูดชื่อก่อนจังหวะพลิก, twist line ≤ 20 ตัวอักษร
- twist ซ่อนอยู่จริง (*Hiding the twist* ใน story-rules): clue ทุกจุดมีงานบังหน้า, caption ไม่ชี้, มีตัวหลอกหนึ่งตัวที่ถูกอธิบาย, ข้อเดาแรกของคนดูไม่ใช่ twist, ฮุก/ชื่อ/ปกไม่เฉลยเกินช็อต 2
- ไม่ใช่ twist ต้องห้าม ("ฝันไป", ต้องรู้ข้อมูลที่คนดูไม่เคยเห็น, ต้องอาศัยบทสนทนาสองคน)
- Survival/ตำนาน: fact ทุก 3–5 ช็อต แต่ละข้อมีภาพ และ **ตรวจแล้วว่าจริงและปลอดภัย** (ค้นเว็บถ้าไม่แน่ใจ; ตำนานเล่าเป็นความเชื่อ ไม่ใช่ความจริง)
- Narrative clarity: One-punchline (อนุมานไม่เกิน 1 ทอด), Action-Motive pair
- ตัวละคร ≤ 3 คนมีชื่อ แต่ละคนมีจุดสังเกต 1 อย่าง; ซีรีส์: ประโยคสุดท้ายเปิดคำถามตอนหน้า
- จำนวนช็อตเหมาะกับ shape ของ family (~25–35 survival, ~20–28 haunting)
- plot hole ที่คนคอมเมนต์จิ้งได้ในประโยคเดียว

## 3. Fun pass

ทำตาม `.claude/story/fun-pass.md` ให้ผลเป็นข้อเสนอ 3 กลุ่ม แยก [ของคุณ | ผมเพิ่ม | ผมตัด] ข้อเสนอต้องอยู่ในกรอบ story-rules (เช่น ไม่เพิ่ม twist ที่สอง, ไม่ทำให้เกินความยาว) และไม่ทิ้งสิ่งที่ prompt ตั้งใจไว้ รายละเอียดที่ผู้ใช้ใส่มาใน prompt (โทน ตัวละคร ฉาก ความชอบ) ถือเป็นข้อกำหนด ไม่ต้องถามซ้ำ
สำหรับ Shorts ให้เน้นเป็นพิเศษ: ฮุกเฟรม 0 (ร่าง 2 ตัวเลือก), จังหวะ "ทุกอย่างถูก ยกเว้นเรื่องเดียว", ประโยค twist, และ cliffhanger

## 4. ส่ง outline ให้ตรวจ (ยังไม่สร้างไฟล์)

แสดงในแชตตามรูปแบบ one-screen outline ของ `twist-idea` §3:
1. ผล audit (ตาราง ✓/✗ สั้น ๆ + สิ่งที่แก้แล้ว)
2. ข้อเสนอ fun pass ให้ติ๊ก
3. ชื่อเรื่อง + logline + twist (ประโยคเดียวต่อข้อ) · family · ความยาวเป้าหมาย · `captionLook`
3b. **Universe**: ระดับการเชื่อม · สถานที่ (รหัส canon หรือ "ใหม่") · ตัวละคร canon ที่ปรากฏ · ผลเช็ก hard canon · สิ่งที่จะลง canon ใหม่ให้ติ๊กรับ-ตัด
4. ตัวละคร (เลือกจาก `src/cast.json` ที่ไม่ retired ตามกฎ 12; สัตว์คู่ใจถ้าเป็นซีรีส์) พร้อมจุดสังเกต ตัวที่เรื่องต้องการจริงแต่ไม่มีในคลัง ระบุเป็น "ตัวใหม่" พร้อมเหตุผล
5. กฎ 1–3 และ **fact พร้อมสถานะ `✓ ตรวจแล้ว`**
6. ตาราง Clue ledger: clue · งานบังหน้า (เหตุผลธรรมดาที่เรื่องให้ไว้ก่อนพลิก) · วาง ×3 ที่ช็อตไหน (ระบุครั้งที่วางแบบผ่านๆ) · คลี่ที่ช็อตไหน และตัวหลอก 1 ตัว
7. beats ตามองก์พร้อมจำนวนช็อต (ตาม shape ใน story-rules)
8. ตอนจบ: twist line + cliffhanger + ชื่อ "ตอนต่อไป" ถ้าเป็นซีรีส์
9. ร่างบรรยาย 2 ช็อตแรก (ฮุก) เป็นตัวอย่างน้ำเสียง
10. **การซ่อน twist** (แทน scorecard ให้คะแนนตัวเอง ซึ่งคนเขียนตัดสินเองไม่ได้): ข้อเดาแรกของคนดูที่ช็อต 5 · งานบังหน้าของแต่ละ clue (คอลัมน์ในตารางข้อ 6) · ตัวหลอกและช็อตที่อธิบายมัน · ผล cold read รอบ A ถ้าทำ (`.claude/story/cold-read.md`) จุดที่ยังอ่อนให้บอกตรงๆ ว่าติดอะไร ไม่ต้องให้คะแนน

จบด้วยคำถามเดียว: อนุมัติไหม / ติ๊กข้อเสนอไหนรับ-ตัด

## 5. หลังผู้ใช้อนุมัติ

1. เลือก slug (อังกฤษ เล็ก ขีดกลาง ไม่ซ้ำ `episodes/`) แจ้งผู้ใช้
2. `npm run new -- <slug> "ชื่อเรื่อง"`
3. บันทึก outline ที่อนุมัติลง `episodes/<slug>/outline.md` (รวมหัวข้อ Universe)
3b. อัปเดต `universe/canon.json` เฉพาะส่วนที่ผู้ใช้อนุมัติ: `episodes.<slug>` (link, place, era), `places` ใหม่, `events`, ตัวละคร `appears`, `threads` ที่เปิดหรือตอบ และถ้ามีสถานที่/กฎใหม่ ให้เพิ่มลง `universe/bible.md` ด้วย
4. ถ้าเป็นซีรีส์และยังไม่มี bible ให้เสนอ `/twist-series` ก่อนเขียน story.json
5. หยุด รายงานว่า outline พร้อม แล้วถามว่าจะเข้า `thai-twist-short` เขียน story.json ต่อเลยไหม ถ้าใช่ invoke skill นั้น (อ่าน `directing.md` ก่อนวางช็อต)

## ข้อห้าม
- ห้ามเขียนเนื้อเรื่องลง `story.json`, ห้ามวาดฉาก, ห้ามเรียก voice/render (เสียเครดิต)
- ตัวละคร: เลือกจาก `src/cast.json` ที่ไม่ `retired` ก่อนเสมอ ห้ามใช้ตัว `retired` สร้างตัวใหม่ได้ **เฉพาะเมื่อเนื้อเรื่องต้องการจริงและไม่มีตัวใดในคลังใช้แทนได้** แล้วแจ้งผู้ใช้ในพิมพ์เขียว ตอนลงมือสร้างให้ทำตาม `/twist-cast` และเพิ่มเข้า `src/cast.json` (กฎ 6 และ 12) ไม่ใช่วาดเฉพาะในตอน
- ห้ามคัดลอกกฎมาไว้ในไฟล์นี้ ถ้ากฎเปลี่ยนให้แก้ที่ `story-rules.md`
- ข้อเสนอที่แตะ twist หรือแก่นเรื่อง ต้องให้ผู้ใช้ตัดสินเอง
- ห้ามคัดลอกกฎโลกหรือรายชื่อ canon มาไว้ในไฟล์นี้ ให้ชี้ไป `universe/` ห้ามเพิ่มหรือแก้ canon เองโดยผู้ใช้ไม่อนุมัติ และห้ามบังคับให้ทุกเรื่องเชื่อมกัน
